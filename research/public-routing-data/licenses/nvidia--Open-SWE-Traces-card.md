## Data Overview

Open-SWE-Traces is an agentic instruction-tuning dataset engineered to advance Large Language Model (LLM) capabilities in automated software engineering. The dataset 
features agentic interaction trajectories captured across multiple open-source execution frameworks and synthesized using diverse, high-performing model families.

* **Task Focus:** Autonomous software engineering and code patch generation (like [SWE-bench](https://huggingface.co/datasets/princeton-nlp/SWE-bench_Verified)).
* **Task Sources**: All underlying issue statements and repository environments are sourced exclusively from permissively licensed datasets:
[Scale-SWE](https://huggingface.co/datasets/AweAI-Team/Scale-SWE),
[SWE-rebench-V2](https://huggingface.co/datasets/nebius/SWE-rebench-V2).
* **Frameworks Used**: Trajectories were collected by deploying agents across five state-of-the-art framework architectures: [OpenHands](https://github.com/OpenHands/OpenHands), 
[SWE-agent](https://github.com/swe-agent/swe-agent),
[mini-swe-agent](https://github.com/swe-agent/mini-swe-agent),
[opencode](https://github.com/anomalyco/opencode),
[claude-code](https://github.com/anthropics/claude-code).
* **Trajectory Generation Models**: To ensure broad behavioral diversity, trajectories were synthesized using leading models from the following families: MiniMax, 
Qwen, DeepSeek, GLM.

This dataset is ready for commercial/non-commercial use.


## Data Fields
|Field|Type|Description|
|:---|:---|:---|
| `instance_id` | `string`| Unique identifier for the instance (from nebius/SWE-rebench-V2)|
| `repo` | `string` | GitHub repository in `owner/repo` format|
| `license` | `string` | SPDX license identifier of the repository|
| `language` | `string` | Primary programming language of the repository.|
| `trajectory_id` | `string` | The identifier unique for each collected trajectory.|
| `messages` | `list` | Complete conversation history with roles: 'system' and 'user' (initial prompts), 'assistant' (model reasoning/actions) and 'tool' (environment observations).|
| `tools` | `list[string]` | A list of tool definitions available to the agent during execution, serialized as JSON strings.|
| `resolved` | `int` | Indicator of task success: 1 if the agent solved the issue, 0 otherwise. (-1 if the information is unavailable)|
| `metadata` | `dict` | Additional contextual info about the PR task and execution metrics:<br><br>• **`category`** (`string`): The issue classification type (e.g., `"bug-fix"`, `"enhancement"`).<br><br>• **`reference_patch`** (`dict`): Reference ground-truth patch details:<br>&nbsp;&nbsp;&nbsp;&nbsp;— *`patch`* (`string`): The gold patch in unified diff format.<br>&nbsp;&nbsp;&nbsp;&nbsp;— *`num_modified_files`* (`int`): Count of files modified by the gold patch.<br>&nbsp;&nbsp;&nbsp;&nbsp;— *`num_modified_lines`* (`int`): Total lines changed by the gold patch.<br><br>• **`model_patch`** (`dict`): Model-generated patch details:<br>&nbsp;&nbsp;&nbsp;&nbsp;— *`patch`* (`string`): The model-generated patch in unified diff format.<br>&nbsp;&nbsp;&nbsp;&nbsp;— *`num_modified_files`* (`int`): Count of files modified by the model patch.<br>&nbsp;&nbsp;&nbsp;&nbsp;— *`num_modified_lines`* (`int`): Total lines changed by the model patch. |

## Intended use

This dataset is intended for LLM engineers and research teams building autonomous software engineering agents and code-focused assistants. It is suitable for 
supervised fine-tuning and distillation of models that must interpret real-world issue statements, plan multi-step tool use, navigate codebases, and implement fixes 
in a SWE-Bench–style setting. The trajectories can also be used to benchmark and debug agent policies, improve repository-aware reasoning, and study robust, 
regression-free code editing behaviors in both academic and production environments.
